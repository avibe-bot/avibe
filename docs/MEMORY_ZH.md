# 记忆

Avibe 记忆会把符合条件的 Workbench 和私聊消息提炼为按用户隔离的画像、事件与事实。
在**设置 > 记忆**中可以查看状态、当前画像、搜索结果、设置和处理日志。

## 处理日志

「日志」标签页是安装运维者视图，会展示所有有效项目和用户。每条记录及详情都会
明显标注完整的 **Project ID** 和 **User ID**，并展示消息从捕获、创建 memcell、运行处理
策略，到触发画像与当前索引状态的过程。当前，经过认证的本地或 Avibe Cloud 记忆页面会
获得这一安装级日志读取范围；画像和搜索读取仍按用户隔离。某个来源数据库缺失、忙碌、
格式异常，或关联标记已经过期时，对应部分会显示为不可用，其他部分仍会继续显示。

提供方调用只有在能够根据确切 provenance 证明属于所展示的项目和用户时，才会关联到时间线。
安装级视图不会放宽这些关联条件：外部、损坏或多用户 memcell 会被过滤，详情
读取也会先从记录本身取得真实范围，再读取运行、捕获和调用。

## 提供方负载日志

记忆启用时，会始终记录提供方负载诊断。旧配置中的
`memory.diagnostics.log_provider_calls` 字段仍会被兼容加载，但会被规范化为 `true`，
设置页不再提供关闭开关。

Avibe 会保留记忆处理过程中 LLM、多模态 LLM 和 Embedding 调用里经过脱敏且有
大小限制的请求与响应字段。它不会存储 Embedding 向量、附件字节、sidecar 原始
stdout/stderr，也不会记录无关的 Search 和 Get 调用。密钥、已配置的提供方 URL 和本机
绝对路径会被脱敏；过大的字段会截断或替换为省略标记。诊断负载仍可能包含敏感对话文本，
应按敏感数据控制安装级日志的访问。

记录在正常过期或执行「清除全部」前仍可读取。即使记忆已禁用，留存清理仍会继续：记录
最多保留 14 天，并且只保留最新的 5,000 次调用。

## 恢复阶梯

请按以下顺序操作，从破坏性最低的操作开始：

Avibe 会拒绝相互冲突的记忆维护请求。请等待当前操作结束，再开始其它操作。

1. **重启引擎** — 用于暂时性的记录器或引擎故障。此操作要求记忆已启用。它只重启记忆
   引擎，不会更改设置、重建索引或删除已保留的数据。
2. **修复索引** — 重启后索引健康警告或待处理工作仍未消除时使用。此操作是否显示在
   **引擎状态 > 可用能力**下由 `repair_available` 控制；仅健康快照不可用不会将其隐藏。
   实际执行修复还要求记忆已启用，并且当前 Memory Runtime 和 sidecar 可用。记忆已禁用时
   请求会被拒绝，运行时或 sidecar 不可用时修复会失败。修复会重新扫描 Markdown 记忆并
   排空待处理工作，同时保持引擎可用；现有索引会保留，但过程可能消耗 Embedding API
   配额。**记忆索引修复完成，但健康状态有警告。**表示修复已结束，但返回的健康状态仍不
   正常。处理报告的问题后，再次选择**修复索引**；修复失败时也可用相同方式重试。
3. **重建索引** — 更改 Embedding 端点或模型后使用，也可用于恢复待处理的重建。确认
   **保存并重建**后，会先保存新设置，再重建本地向量索引，并保留 Markdown 记忆。如果
   重建在结算前失败，已确认的更改仍会保存，恢复意图和重建警告会继续保留，并且
   **重启引擎**仍不可用。按需修正端点或 API Key 后，选择**重试重建**。如果重建已经完成，
   但随后的引擎或 sidecar 激活失败，恢复意图可能已被清除。请修复运行时问题，再选择
   **重启引擎**；此时可能不再提供**重试重建**。
4. **工厂重置** — 仅当以上操作都无法恢复记忆时，才将它作为最后手段。只有已固定并安装的
    Memory Runtime 有效时，**设置 > 记忆**下才会提供此操作。它会永久删除且只删除已安装的
   记忆根目录（`memory`）和可变记忆状态根目录（`state/memory`）。只有切换成功后，才会
   启动全新且可用的记忆状态。记忆设置和凭据、已固定并安装的 Memory Runtime、原始 Avibe
    聊天记录以及这两个根目录之外的数据都会保留。如果删除后引擎或 sidecar 激活失败，
    `memory` 和 `state/memory` 下的旧内容仍已删除，但全新运行时的构建过程可能已重新创建空的
    或不完整的根目录。记忆会保持封锁且不可用。请修复运行时问题，再选择**重试工厂重置**。

### 工厂重置

当记忆状态损坏到无法通过重建恢复时，可在「设置 > 记忆」的破坏性操作区域使用**工厂重置**。只有固定的 `memory-runtime` 运行时已安装且状态为就绪时才能执行；如果固定工件无效，请先在「设置 > 依赖」中修复。确认对话框会等待五秒，并明确列出将删除的两个可变根目录：`<effective_home>/memory` 和 `<effective_home>/state/memory`。

工厂重置会保留记忆设置、凭据和已安装的运行时。请求会等待最终结果，并分别报告两个根目录是否删除，绝不会把部分删除说成完整成功。崩溃后，持久化的 `factory_reset` 恢复意图让「重试工厂重置」可以幂等地完成剩余删除；恢复待处理期间，其他记忆操作均保持禁用。工厂重置不是安全擦除，也不会删除原始聊天或已发送到远程端点的副本。
