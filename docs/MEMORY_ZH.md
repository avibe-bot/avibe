# 记忆

Avibe 记忆会把符合条件的 Workbench 和私聊消息提炼为按用户隔离的画像、事件与事实。
在**设置 > 记忆**中可以查看状态、当前画像、搜索结果、设置和处理日志。

## IM 附件捕获

记忆可以从 Slack、Discord、Telegram、飞书/Lark 和微信已绑定的一对一会话中提取受支持
的附件。仅当记忆已启用，并且在**设置 > 记忆**中完整配置多模态 LLM 端点后，此能力才
可用；它不会改变发送给 Agent 的文件。

只有人类直接分享的普通文件才符合条件。机器人、系统、转发、编辑、引用、富内容和无法
识别的原生消息形状都会被排除。随后，Avibe 使用同一套格式与内容策略检查每个符合条件
的文件。支持纯文本、Markdown、CSV/TSV、VTT、PDF、位图图片、音频、HTML 和 EML。
不支持或格式异常的文件会被单独跳过，符合条件的文本和其它有效附件仍可进入捕获。

每轮最多捕获 8 个附件，单个附件最大 25 MiB，总计最大 100 MiB。通过准入的文件会复制
到 Avibe 私有存储，并保留到持久化记忆投递完成。提取后的内容可能发送给已配置的多模态
提供方，因此请按数据处理要求配置该端点。清理记忆数据会删除本机仍保留的附件包，但
无法删除提供方已经接收的副本。

## 已处理事件列表

`vibe memory list` 只读取当前范围内用户和项目的有效、活跃、已处理事件，不包含画像、
Agent 记忆、原子事实、未处理消息或已被取代的事件。单项目读取严格使用 EverOS 从 1
开始的页码，并固定按时间倒序排列。经过验证的设置页可通过 Avibe 生成的有界、带版本
cursor 聚合同一用户的多个项目；Agent CLI 不能请求 `all`。JSON 会保留提供方的不透明
entry id，作为未来检查入口。列表读取不会把 Search/Get 负载写入提供方诊断，也不会调用
LLM、Embedding 或重排序服务。

在**设置 > 记忆 > 搜索**中留空查询，即可按最新优先浏览这些事件。可以选择单个项目或
**我的全部项目**，通过事件摘要下方的页码切换页面，再选择一行打开完整详情。点击
**条目 ID** 芯片会复制提供方的不透明标识符。输入任意非空查询后，同一标签页会切回按
相关性排序的搜索结果。

## 处理预检与可选重排序端点

确认更改 Embedding 端点标识或重试待处理的重建前，Avibe 会分别执行一次有界的聊天
请求和 Embedding 请求。配置可选重排序端点后，预检还会执行一次有界的重排序请求。
提供方失败会显示对应端点、HTTP 状态、提供方错误码和经过脱敏的信息。

**设置 > 记忆**中的第三个处理端点是可选项。要启用固定 Memory Runtime 的重排序能力，
必须同时填写 Base URL、模型和 API Key；添加或更改端点会在保存前执行同样的有界预检。
三个字段全部留空时会继续使用标准记忆搜索层级。移除已保存的重排序端点会清除这三个值，
但不会重建 Embedding 索引。

## 处理日志

「日志」标签页是安装运维者视图，会展示所有有效项目和用户。每条记录及详情都会
明显标注完整的 **Project ID** 和 **User ID**，并展示消息从捕获、创建 memcell、运行处理
策略，到触发画像与当前索引状态的过程。当前，经过认证的本地或 Avibe Cloud 记忆页面会
获得这一安装级日志读取范围；画像和搜索读取仍按用户隔离。某个来源数据库缺失、忙碌、
格式异常，或关联标记已经过期时，对应部分会显示为不可用，其他部分仍会继续显示。

提供方调用只有在能够根据确切 provenance 证明属于所展示的项目和用户时，才会关联到时间线。
安装级视图不会放宽这些关联条件：外部、损坏或多用户 memcell 会被过滤，详情
读取也会先从记录本身取得真实范围，再读取运行、捕获和调用。

## 提供方负载日志

记忆启用时，会始终记录提供方负载诊断。旧配置中的
`memory.diagnostics.log_provider_calls` 字段仍会被兼容加载，但会被规范化为 `true`，
设置页不再提供关闭开关。

Avibe 会保留记忆处理过程中 LLM、多模态 LLM、Embedding 和重排序调用里经过脱敏且有
大小限制的请求与响应字段。它不会存储 Embedding 向量、附件字节、sidecar 原始
stdout/stderr，也不会记录无关的 Search 和 Get 调用。密钥、已配置的提供方 URL 和本机
绝对路径会被脱敏；过大的字段会截断或替换为省略标记。诊断负载仍可能包含敏感对话文本，
应按敏感数据控制安装级日志的访问。

记录在正常过期或执行「清理记忆数据」前仍可读取。即使记忆已禁用，留存清理仍会继续：记录
最多保留 14 天，并且只保留最新的 5,000 次调用。

## 恢复阶梯

请按以下顺序操作，从破坏性最低的操作开始：

Avibe 会拒绝相互冲突的记忆维护请求。请等待当前操作结束，再开始其它操作。

1. **重启引擎** — 用于暂时性的记录器或引擎故障。此操作要求记忆已启用。它只重启记忆
   引擎，不会更改设置、重建索引或删除已保留的数据。如果调用日志数据库损坏，重启后
   记录仍处于降级状态，请在进一步升级前执行**清理记忆数据**。
2. **修复索引** — 重启后索引健康警告或待处理工作仍未消除时使用。只有在记忆已启用且
   `repair_available` 为 true 时才显示**修复索引**（已安装的 Memory artifact 必须声明
   支持修复，并且不能有待处理的重建或 `factory_reset` 恢复意图）。健康快照
   加载成功时，它位于**处理队列**旁；健康快照不可用时则会移到**引擎状态**旁，而不会
   被隐藏。实际执行修复还要求当前 Memory Runtime 和 sidecar 可用。记忆已禁用时请求会
   被拒绝，运行时或 sidecar 不可用时修复会失败。修复会重新扫描 Markdown 记忆并排空
   待处理工作，同时保持引擎可用；现有索引会保留，但过程可能消耗 Embedding API 配额。
   **记忆索引修复完成，但健康状态有警告。**表示修复已结束，但返回的健康状态仍不
   正常。处理报告的问题后，再次选择**修复索引**；修复失败时也可用相同方式重试。
3. **重建索引** — 更改 Embedding 端点或模型后使用，也可用于恢复待处理的重建。确认
   **保存并重建**后，会先保存新设置，再重建本地向量索引，并保留 Markdown 记忆。如果
   重建在结算前失败，已确认的更改仍会保存，恢复意图和重建警告会继续保留，并且
   **重启引擎**仍不可用。Embedding 端点或模型修正会改变向量空间标识，因此必须编辑后重新确认
   **保存并重建**，不能通过**重试重建**应用。在重建标记待处理期间，LLM 端点或模型修正也
   可以正常保存，然后选择**重试重建**；任一提供方仅修改 API Key 也可以在标记下保存，不会
   触碰受保护的运行时，之后再选择**重试重建**。如果重建已经完成，但随后的引擎或 sidecar
   激活失败，恢复意图可能已被清除。请修复运行时问题，再选择**重启引擎**；此时可能不再
   提供**重试重建**。

### 清理记忆数据

在重新初始化记忆前，如果保留的记忆数据或调用日志数据库损坏，请先使用**清理记忆数据**。该操作
会创建并验证队列、提供方数据、调用日志和固定附件的私有快照，然后在维护日志保护下仅
删除 Avibe 所拥有的这四个表面。它不会删除 `memory` 或 `state/memory` 根目录本身、原始
Avibe 聊天、已经发送给提供方的副本，或这些表面之外的数据（包括日志、备份和用户创建的
快照）；它不是安全擦除。

如果**清理记忆数据**被中断，「处理记录」会针对该操作显示明确的**继续清除**和**中止并恢复**操作。
**继续清除**会继续日志记录的删除；**中止并恢复**会从已验证的快照恢复所有表面，并且只有在初始
快照完整后才可用。不会自动恢复，在其中一个操作得到终态前，记忆会保持封锁。

4. **重新初始化记忆** — 仅当以上操作都无法恢复记忆时，才将它作为最后手段。该操作位于
   **设置 > 依赖**的 Memory Runtime 卡片中。只有已固定并安装的 Memory Runtime 有效时才可执行；
   它会永久删除混合存储位置 `memory` 和 `state/memory` 中的本机记忆数据和相关运行状态。
   前者可能包含画像、事实、索引、调用诊断和运行文件；后者可能包含处理队列、恢复进度和
   协调状态。只有切换成功后，才会
   启动全新且可用的记忆状态。记忆设置和凭据、已固定并安装的 Memory Runtime、原始 Avibe
   聊天记录以及这两个存储位置之外的数据都会保留。如果删除后引擎或 sidecar 激活失败，
   `memory` 和 `state/memory` 下的旧内容仍已删除，但全新运行时的构建过程可能已重新创建空的
   或不完整的目录。重新初始化会分别报告两个存储位置的终态，因此部分删除的结果可能显示
   一个位置已删除、另一个被保留或部分删除；应以两个位置各自的结果为准，不要将其视为完整清理。
   内部 `factory_reset` 恢复意图待处理期间，记忆会保持封锁且不可用。界面会分别显示两个位置的可见
   状态：**已删除**、**已部分删除**、**不存在**或**已保留**；请分别查看两个状态，不要等待界面
   提供具体错误原因；失败提示是通用的。如果某个位置为**已保留**或**已部分删除**，请查看对应技术路径的
   服务日志和文件系统权限，并修正删除失败。如果删除已完成，但持久化的 LLM 或 Embedding 接口地址、模型
   或凭据无效，导致引擎或 sidecar 激活失败，请在 `factory_reset` 恢复意图待处理期间于「设置 > 记忆」中修正相应
   处理设置。端点修正无法解决根目录删除失败。处理与当前状态对应的原因后，选择**重试初始化**
   继续恢复。重试具有幂等性：会继续尚未完成的删除，同时保留两个存储位置实际结果的真实报告。

### 重新初始化记忆

当记忆状态损坏到无法通过重建恢复时，可在「设置 > 依赖」的 Memory Runtime 卡片中、紧邻「修复」使用**重新初始化记忆**。操作会保持可见，但只有固定的 `memory-runtime` 运行时已安装且状态为就绪时才能执行；如果固定工件无效，请先修复。确认对话框会等待五秒，并说明操作将删除本机记忆数据和相关运行状态，然后尝试启动一个全新的记忆引擎。对话框也会提示：即使删除成功，新引擎仍可能无法启动，旧数据不会恢复。两个混合存储位置分别标为**主要记忆存储**和**记忆状态存储**；对应技术路径 `<effective_home>/memory` 和 `<effective_home>/state/memory` 仅作为补充详情显示。

重新初始化记忆会保留记忆设置、凭据和已安装的运行时。请求会等待最终结果，并分别报告两个存储位置是否删除，绝不会把部分删除说成完整成功。崩溃后，持久化的内部 `factory_reset` 恢复意图让「重试初始化」可以幂等地完成剩余删除；恢复待处理期间，其他记忆操作均保持禁用。重新初始化不是安全擦除，也不会删除原始聊天或已发送到远程端点的副本。
