# AV-12 backend handoff

See `bound-network-position-trust.md` for the reviewed rules. This is the integration contract, not release copy or a claim that AV-13, the opening-page work, or Incus verification has landed.

## Old address and local operation

* A positively readable unbound config keeps its configured setup access. Binding is the saved identity, **not** connector status. The stored setup host, port, projects, account credentials, browser sessions, and remote On/Off choice are not changed. Unknown, recovered, partially paired, or reset-in-progress state does not grant setup-network Owner. Direct loopback remains a repair path.
* `_SetupNetworkMiddleware` runs before routing (including slash redirects), below the invalid-Host, managed-name and direct-ingress guards. No request header is converted into the socket peer. A local tunnel or explicitly trusted proxy may supply the secure scheme, not owner identity. The canonical instance address continues through the normal sign-in, role, device, resource, public share and callback rules. Do not treat a recognized address as proof of an authenticated user.
* On the old private origin, an eligible document gets a finite 200, no-store/no-referrer, without a redirect or private target. `_retired_setup_notice` is the isolated presentation seam. **Claude:** replace its interim reused translation with the agreed two alternatives: the fixed `https://avibe.bot/app` account list, or open Avibe on the computer running it. No connector/tenant information, personalized link, claim parameters, script, or external asset. Same page when remote is Off. A machine request, including a claim poll, gets a denial (`503 remote_access_host_mismatch` on the bound old address); that alone is not evidence that a particular claim succeeded. A valid pre-publication claim return still completes. Only `GET /health` from the previously admitted private network retains bare `{"status":"ok"}`; no Owner principal is constructed for that response.
* True IPv4/IPv6 loopback and the **explicitly declared** Docker host-loopback publication keep local Workbench access. A Docker declaration is not evidence for direct-only APIs. **Docker docs:** require the actual loopback-only host publication, recognized bridge peer and loopback Host, with no forwarding metadata. A false declaration can let other devices in without signing in. A same-user process or forwarder indistinguishable from real loopback is outside this listener's boundary. Headless recovery requires existing OS access (private SSH forwarding to loopback, or local `vibe remote start` for an already configured connector). Do not automatically turn remote on, reset, or broaden the bind.
* WebSocket inputs and outputs, and SSE output, recheck the persisted position. Idle checks start at one-second intervals; OS scheduling and transport may delay observation. Pre-publication work and bytes already handed to the transport cannot be recalled. CLI calls targeting a bound local UI use the listener's same-family loopback.

## Push: foreground contract for the browser / native App writer

At first binding publication or first startup on an already bound install, formerly enabled/provider-invalidated anonymous rows move to a disabled namespace. This does not clear a signed subject's subscriptions or touch the Desktop OS notification settings. SQLite `state_meta` carries the binding receipt (no migration). File publication under the SQLite writer, transaction-time registration checks and dispatch-time row/receipt checks fence stale grants. A crash after the file replacement but before DB commit leaves anonymous sends and registrations closed until startup reconciliation. No lock is held during provider I/O. Native Health wakes use only authorized signed subjects, not `local`.

| Client intent | Existing JSON endpoint and new behavior |
|---|---|
| Read / foreground status | `POST /api/web-push/status` with the existing endpoint, subscription and device ID when available. `current_subscription_binding_retired: true` means **eligible for host repair**, not enabled and not an opt-out. Status cannot turn a retired row on. `current_subscription_repairable` continues to describe ordinary provider invalidation. With no live subscription query the remembered endpoint. |
| Automatic restoration | Only on foreground open, after reading persisted disable/sign-out intent and checking **already-granted** notification permission. Do not prompt. Submit `POST /api/web-push/subscriptions` with `binding_repair: true`, `subscription: {endpoint, keys}`, `device_id` when known, `previous_endpoints` when rotating, optional `device_label`. Do not also set `background_rotation`. Same endpoint needs its matching keys. For an unused replacement the server checks an eligible remembered predecessor and device match. A consumed predecessor cannot authorize another repair. Successful restore is scoped to this host grant; no other browser is restored. |
| Explicit enable | A real user-enable action should include `explicit_enable: true` on the normal subscriptions POST. Do **not** attach this flag to foreground reconciliation, retry, implicit native default, worker or permission checks. On a bound host a legacy flagless POST may confirm an already active row, but cannot create or revive a grant. Signed and unbound registration semantics otherwise remain unchanged. Preserve the original intent on pending native retries; unknown intent is not an explicit enable. |
| Explicit disable / device sign-out | Existing DELETE with endpoint and device ID; retired eligibility is also invalidated. Existing provider-invalidated and explicitly stopped states are distinct. Honor disabled intent even while cleanup is pending or the provider rotated; do not fall back to a normal creating POST after `accepted: false`. If subscribed locally just for a failed conditional repair, clean up that attempted subscription without re-enabling it. |
| Service worker / provider rotation | Continue `background_rotation: true` only for an active/provider-repairable predecessor. It cannot claim a retired, explicitly stopped, or signed user's grant for a local device. |

Claude owns `ui/src/lib/webPush.ts` and transport types (`WebPushStatus`, `ApiContext.subscribeWebPush`); extend the payload **without** changing what the existing `backgroundRotation` positional argument means. Cover current and lost browser subscriptions, native pending registrations, separate accounts, denied/default permission (no OS prompt), explicit Off and simultaneous disable/return. The Desktop shell's independent native notification channel requires no reset or change here.
