# Runtime pairing: one evidence decision for recovery

All eight entry points must distinguish permission to recover from the operation they are capable of performing. Read the protected journal, its schedule, the acceptance marker, installation identity and binding fingerprint into one snapshot. Pass that snapshot and a clock value to a pure decision function. The outcome distinguishes fresh input/reservation, same-request dispatch, wait, local archive, known terminal and reconciliation. Project `can_resume` and `replay_state` from the same result. A status read is advisory; before a mutation re-read under the existing send/config locks. Keep the existing admission, same-input, claim/guard matching, and local publication checks; a classification is never new authority.

Precedence: foreign acceptance or unaccounted delivery blocks; malformed acceptance blocks except local completion of a trustworthy compatible receipt (an identifiable foreign claim still blocks); validate installation/source/target; a recorded Desktop expiry outranks an old dispatch schedule. Fresh input needs a clean start or a permitted live handoff. Absent evidence is not evidence of a clean start after a reservation. A saved pending/rate-limit floor outranks active retry requests. Marker validity follows the producer, not current time: a valid historical timestamp stays parseable, while a malformed timestamp or truncated binding generation is damage.

Acceptance: run through A–H using temporary files, real locks and isolated fixture peers. Record every accept and redeem at the first line of the fake transport, independently count issuance and consumption by authorization, and inspect the ledger outside runtime exception handling. Deliberately inject a forbidden fixture delivery and prove the external oracle catches it. Exercise a real prepared Desktop guard, confirmed expiry through both guarded and explicit same-key entries, receipt/foreign-marker status vs action, and paired good/damaged marker ticks between the 90-second floor and 900-second deadline. Do not count a successful local test as native host or live control-plane validation.
