# AV-12 — network position is not an account on a bound Runtime

Internal acceptance contract for independent review, **before implementation**. Base `03b4d20de2b9249d8ee5ce17de022f8b81fbe54e` (fetched master, 2026-11-22); compare AV-13 `e063b2305` and Devices page `2586fbf11`. References below are to base unless qualified. `UI` = `vibe/ui_server.py`. This is not Product copy or a security incident report.

**Rule:** Private-network admission is setup authority, not a durable session. On a clearly unbound computer retain today's admission. From publication of the binding, only direct loopback or the explicitly declared Docker host loopback described below may acquire implicit Workbench Owner. All other *interactive Workbench* access uses the existing authenticated instance address, role and resource checks. No local-to-account cookie, grandfathered IP, new credential, opt-out flag, automatic enable, account creation, redirect from LAN to the instance name, or change to `setup_host` on upgrade.

## Binding signal, upgrade, and the limits needing review

1. **Published identity, not runtime connectivity.** `config/v2_config.py:3939–3966` makes `is_runtime_paired()` false when disabled. `remote_access.status()` uses a different “paired” (`vibe/remote_access.py:1279`), and `stop()` withdraws the connector-request file, not credentials (`:4586–4603`). Use one binding decision everywhere. **Only readable, positively blank pairing identity and positively absent reset intent permit the unbound admission rules.** An intact identity (`vibe/personal_claims.py:33–42`) means bound even if disabled, stopped, offline, missing a public URL, or auth refresh fails. A reset record closes position trust for its entire lifetime, including after config clear; use AV-13's reset evidence, not just the config fields (`e063b2305:vibe/binding_admission.py:50–57`; `vibe/binding_reset.py:139–181`). Partial identity, unreadable/ambiguous state of either artifact, or recovery of the relevant config/whole file (`config/v2_config.py:1479–1492,4128–4144,4151–4188`) has the same closed admission as bound, without asserting a healthy binding or advertising a hostname. An installation UUID alone is **not** an account. Even first-run missing config is not proof of unbound for network-position Owner; preserve the legitimate direct bootstrap and repair path. No broad config flag or always-on account check.
2. **First request after upgrade**, not next login, re-pair, restart of a tunnel, or expiry of a grace period. Preserve saved UI binding, workspace, claim state, public URL, login secrets, device registry/grants, and requested On/Off. Gate from persisted state before serving confidential data. Old private bookmark, PWA and API polling no longer open the workspace or assert Owner, even on the host's own phone; same machine opens loopback (same port/family). A signed-in user opens the account's own instance remotely; existing valid session still works, new browser signs in, role/ACL applies, Devices shows the signed-in client. Replace LAN home-screen shortcut if desired: old and public origins have separate storage and permissions. A stale local tab can't be made to forget its prior content; its next server request/stream isn't authorized. **No transfer of local-only rights** such as local terminal namespace/enrollment to the public session. No mass sign-out, consent change, host rewrite or background enabling.
3. **Off**: a signed-in account does not make an offline/disabled ingress reachable. Steady-state native host has real loopback even on explicit private bind (`vibe/desktop_runtime.py:282–314`, UI:20766–20776); open it at the computer and explicitly enable the desired connection, keeping the same binding. For an operator of a headless server, “on the computer” can mean an already-authorized SSH session: use private SSH port forwarding to its loopback UI, or run `vibe remote start` there to restart an already configured connector. That requires independent OS access; it is not a guest/LAN recovery grant or proof of physical presence. For a container use the explicitly declared host-loopback publication, or authorized container-side administration. The previous LAN browser may have been the *only convenient human entry*, not a surviving remote path through sign-in. No “signed in means available”, no automatic switch-on, no reset as a recovery tip. Generic old-address page must not say access is On just because bound. With no listener/route no page can be sent.
4. **Publication/liveness:** **zero input grace period** for position-admitted WebSockets. At every received application message, after receive and before handing it to the PTY/HMR handler, check the persisted decision in item 1; never reuse the handshake's decision or wait for a notification. A message admitted before publication is in flight; the first message received after publication cannot act. Check the same decision before sending protected output/Show or Workbench events, so even a delayed timer cannot release new data after resumption. Idle streams/sockets recheck at intervals of **at most 1 second** (the existing socket authorization cadence, UI:311,4557) and initiate closure on the first scheduled check; scheduling or transport delays may defer observation of the close, not admission of another message. Test the first input and output **before** the next idle tick, plus idle closure on that tick, after an independent process publishes to the shared root. Keep true loopback and authenticated public streams open as controls. This is not retroactive interruption of previously authorized commands or recall of buffered network bytes.
5. **Decisions (November 22, 2026):** retain explicit Docker host-loopback declarations; retire previously anonymous local push at binding or bound upgrade and support prompt-free host re-registration when permission remains. Absolute physical locality is not attestable without a different owner channel. For AV-13 use existing direct/reset contract and an integration gate (or land #4133 first); release must not leave an alternate ordinary remote unbind. For a plain notice apply it to normal **document navigation**; direct-only API errors, bad authorities, health, OAuth/state handling, WS and machine reads have distinct non-success results, not 200 HTML for scripts. No new authentication scheme for intentionally public Shares, native device proofs or IM service traffic.
