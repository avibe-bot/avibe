# Isolate interactive control from Turn execution

**Decision requested for 3.2.8 (draft; not an implementation or a 3.2.7 gate).** The component that accepts Stop must not need the interpreter, heap, database transaction, executor slot or output pipe of the Turn being stopped. Recommend a small local controller and process-isolated execution. Moving the same code to threads or making collection less frequent cannot give that property. Do not start by changing prompt storage or rewriting a provider.

## Evidence and scope

The Web/UI server already has its own process; IM transports have their own threads, and native agent CLIs and shell job wrappers already have process boundaries. The common dependency is controller admission, scheduling, Vibey's `Agent` loop and the Model Hub gateway. `modules/agents/vibey/agent.py` retires idle Session runtimes, but concurrent active turns build contexts and consume streams in that same interpreter. Sending a request to a different process and then forwarding its entire JSON body or synchronously draining its stream through the controller would recreate the problem.

- Before #3937, a completed model attempt retained its request graph until the Turn ended. In a 617k-token, 96-tool-round synthetic Turn, releasing that graph reduced peak RSS from 323 to 70 MiB and longest automatic full collection from 343 to 56 ms. This was a retention bug, not the whole architecture.
- A 7.4-hour rc14 field window had 3,066 requests, 41 distinct Sessions (not 41 simultaneous), and a longest Turn of 82 requests. Slow collections still took 39 seconds/hour; median 0.25 s, maximum 0.72 s, none over 1 s. Four ~2-second heartbeat misses instead sampled a reverse successor SQL lookup and job setup. #3960 bounded the lookup and moved setup off-loop without changing Stop ownership.
- A 32-context synthetic workload retained 1.42M tracked objects. Simply sharing immutable scalars and tuples saved **zero** tracked objects: Python was already sharing them. Sharing frozen text records reduced objects, but a mutating hook could alter stored history. Our first safe-sharing experiment therefore shipped nothing. A 3.15 startup freeze missed the later heap; raising allocation thresholds reduced collection frequency, not the worst observed pause. On rc16 at light use the field report was still **103 collections over 0.2 s/hour**, median 0.23 s, max 0.78 s. It is not a throughput-matched comparison.

## Alternatives to compare

| Choice | What it isolates or removes | What still couples users | Cost and disposition |
|---|---|---|---|
| Stop at rc16 | Already removes old-attempt retention and two specific stalls | Future collections, accidental blocking calls, long callbacks, gateway work | No migration; credible if observed responsiveness is sufficient, not a structural guarantee |
| Enforce a non-blocking controller | Worker/executor for filesystem, spawn and database waits; bounded query plans | Python heap/GC and CPU remain shared; queueing a critical operation behind normal work is still a wait | Useful in every design; lint known blocking APIs, test actual event-loop deadlines, fault-inject slow calls. A watchdog sample alone is not a deterministic CI test |
| Executor process per active Turn | Independent interpreter and heap; a crashed or collecting worker cannot stop another interpreter | CPU, memory, SQLite writer and I/O are physical shared resources; starting 32 full application runtimes may itself make the machine unusable | Preferred boundary, with bounded admission and measured worker footprint. Idle Sessions get no process |
| Small fixed pool, multiplex many Sessions per worker | Lower startup/RSS; control process still independent | One slow Turn stops unrelated streams on the same worker; a wedged Turn cannot be killed alone | Useful comparison, not equivalent to one execution owner per active Turn. Prefer exclusive worker leases and an explicit queue over silently sharing a failure domain |
| Immutable append-only context segments | Share immutable *bytes*, not frozen Python objects; decode into private mutable values only where required | GC for active decoded requests, DB scans, spawn stalls and gateway CPU still exist | Potential worker memory optimization, not the separation boundary. Introduce only after equivalent rendered bytes and measurable memory/admission gain |
| Native hot path | Native buffering/byte relay can avoid Python object churn in a measured bottleneck | A blocking native call on the controller thread still blocks it; crash/ABI/packaging risks | Defer language choice. A narrow independently restartable helper is preferable to rewriting hooks, projection and all four adapters |

## Target boundary

```text
Web/UI process   IM transports   local clients
       \              |             /
        controller: routing, bounded status, independent control mailbox
             | control commands / durable receipts        ^ small events
             v                                            |
        turn authority / persistence lane            event relay (bounded)
        SQLite Turn FSM, generation, checkpoint            ^
             | launch/resume by IDs                       |
             +--> supervised exclusive Turn worker -------+
                  projection, hooks, provider adapter, tools
                    | direct model payload/stream | job wrapper
                    v                              v
                local Model Hub data plane      jobs / existing custody services
```

Draft directions: keep `SessionTurnManager` authoritative; do not add a second queue or transcript. Stop *accepted* means intent was durably recorded; it is not *stopped*. Replace preserves the existing durable successor link. Workers are disposable; the record is not. Separate gateway payload processing and bound event bytes so moving only the inner agent loop does not leave the same unbounded work on the controller. This is fault containment for one user's machine, not a security sandbox or a remote cluster.

## Ownership and failure protocol

**Control is a latency budget, not a second source of truth.** The controller loop reads small envelopes, puts them in bounded mailboxes and updates bounded per-active-Turn status. The existing transactional authority serializes state transitions off-loop, with a reserved lane for interactive control and short indexed transactions. A priority queue cannot preempt an already-running SQLite writer: no encoding, model calls, filesystem walks or awaiting IPC while holding a write lock. If storage is unavailable, report that durable acceptance is pending or failed; never acknowledge a commit that has not happened. The distinction between "the transport answered" and "the command took effect" must be visible in latency tests.

**Execution lease.** Key work by `(session_id, turn_id, existing start_attempt_id, runtime generation)` and monotone committed sequence, not a PID. Atomically claim exactly one live writer per Session using the current Turn/delivery FSM. Start or resume the worker by identifiers and a committed cut; do not pickle an Agent, credentials or a decoded transcript. The worker reads that Session's canonical rows from a short-lived read snapshot, closes it before waiting on a provider, and submits append/settlement operations through the existing commit owner. Preserve dedupe keys for consumed input, response rows and tool-call results. Rejected stale messages cannot advance a sequence, authorize a tool or start a successor. A worker should not be able to block control by holding a SQLite write transaction. Large append data must bypass the control mailbox: a bounded storage writer can take ownership of a local staged body identified by ID, validate/commit it, then return the committed row ID. Define orphan staging cleanup before switching writers. No new authoritative event store.

**Model data and streaming.** Keep the current request builders, transform rules, provider selection, refusal rendering and HTTP serializer. Move code ownership, not its representation. The worker executes hooks on isolated mutable requests; provider bytes and auth are assembled at the same logical boundaries as today. The gateway's streaming/data path needs process isolation too; configuration and routing authority need not move with it. Bind a request to a generation and a short-lived route capability through existing local auth/custody boundaries. Never log headers or persist raw credentials in IPC. Direct sidecar and avault demonstrate local managed lifecycles, not reusable authorization to read secrets. The control process must not proxy megabyte bodies or fan out every delta. A byte-bounded relay forwards ordered deltas; a slow subscriber may drop *only transient display* and resync from committed records. Never drop an input, tool completion, terminal receipt or durable queue transition. Backpressure for one stream must stop that producer, not all workers. Give cancel/health their own bounded channel and scheduling quota, not a higher priority in a single full bulk pipe.

**Stop, replace and replay.** Persist the existing Stop/replace intent before claiming success. A worker acknowledges that it saw the fence, stops issuing external work, cancels the provider and reconciles foreground job ownership; handed-over jobs follow their existing contract. Commit terminal state once. The controller can answer status and other Sessions meanwhile, but must not start a replacement until the existing durable predecessor and successor checks allow it. A missed deadline may terminate that worker's process tree only after the durable intent and generation fence are present; merely killing a PID is not settlement. After worker death, reconcile by committed cut, attempt identity and job records. Output seen before a response commit is speculative. Do not repeat a command or provider send with an unknown irreversible outcome on the assumption that it did not happen; use the current recovery rule or surface ambiguity. Controller death closes leases; on restart, check survivors before reclaiming. Worker death while another worker is active must not interrupt the other stream. Treat these crash cuts as tests, not inferred guarantees.

**Resource ownership.** An exclusive process is for an *admitted active Turn*, not indefinitely per Session. A bounded reserve of prewarmed workers may amortize import time, but initially exit workers after one Turn; reuse only after proving cleanup of hooks, pending Tasks, environment, cwd, handles and route state. Charge active decoded bytes, resident worker footprint and stream queues to admission. Reserve memory and scheduling headroom for control on a one-user machine; a fixed process count is not a memory budget. A saturated machine queues new work durably while Send and Stop still answer. Existing streams may still be slow due to OS scheduling, swap, disk or upstream contention. This design promises no single worker's Python pause or queue is **required** for control progress; it cannot promise a hard real-time bound on arbitrary hardware.

## Delivery slices and cost

Engineering estimates are **Agent-hours**, excluding owner reading, CI queue time, release observation and platform access. Keep each transition reversible at a Turn boundary; no long-running Turn changes engine mid-flight. Avoid exposing an experimental user setting.

| Slice (a working product after each) | Estimate | Gate / failure that rejects the change |
|---|---:|---|
| 1. Pin correctness and latency baselines on existing execution; add controlled slow disk, GC, worker exit and slow subscribers to a hermetic harness | 12–20 | Compare actual HTTP bodies and cache-prefix bytes for all four protocols, with realistic hosted records, retries, changing routes, compaction, mutable hooks, historic fixtures; independent control probe, not just internal timings |
| 2. Separate gateway data path/control mailbox and reserve bounded persistence capacity; leave execution in-process | 32–56 | Large sends, slow client and SQLite contention cannot starve a status probe. Test config cutovers, cancellation, local gateway auth, stream ordering and restart. If full bodies traverse controller, this slice is unfinished |
| 3. Introduce typed local execution contract, run it against the old in-process implementation first, then an isolated worker with recorded providers | 32–52 | Version mismatch fails before admission. Old/new implementation emit identical durable rows and wire bytes; reject duplicate/stale completions. No production dual sends or duplicate tool execution |
| 4. Ship exclusive worker for new compatible Vibey Turns; supervisor/recovery, jobs, Stop, replace, steer, queue, resume and fork through the real host | 60–100 | Kill at every commit/ack boundary including job go/abandon. Prove no lost inputs or duplicate effects; preserve side-turn policy and attempt accounting. Roll back by routing **new** Turns to prior backend; existing work drains or recovers |
| 5. Resource caps, packaging and closure on all supported systems; remove the legacy path once acceptance holds | 32–56 | Cold and warm startup, handle/FD leaks, idle memory, aggregate resident memory, fairness, many queued Turns, service upgrade. Use Windows spawn and job-object ownership; avoid requiring `fork`; test macOS app signing/child reaping and Linux process groups, low-memory/cgroup behavior |

**Total: 168–284 Agent-hours**, not a promise that every slice fits one RC. Persisted format or simultaneous backend cutover would increase this estimate. Optional segment-backed worker memory is a separate 32–64 hour investigation and is not on the initial correctness path. Prototype it *after* measuring real worker memory: key immutable bytes by canonical row/version, enforce compaction/fork lifetimes, never use segment boundaries to change model ordering, and materialize privately for hooks. Reject it if read amplification, decoding latency or migration risk outweigh admission gains. A native helper has no credible estimate without a measured bottleneck and an ABI surface; do not schedule it yet.

## What would change the recommendation?

If the controller stays responsive but a useful number of workers cannot fit on the supported memory floor, start with a small number of exclusive leases plus durable queueing; measure queue time separately from interface latency. If other Sessions' streams must make progress simultaneously beyond that cap, immutable worker data or more efficient workers become prerequisites. If a data-plane split alone meets isolation and field targets for the actual workload, ship it and reassess the remaining migration rather than automatically paying the full cost. Unknowns include per-worker imports on packaged Windows, pressure from other desktop software, policy for ack loss after external side effects, whether existing host hooks assume in-process controller objects, gateway routing under reload, and which real operations remain in the shared storage lane. Inventory each host callback before production cutover. The final gate is owner-machine observation, not an artificial claim that a prototype proves all of these.

## Prototype evidence: launching the workers is itself a control-plane workload

**Result:** separate interpreters protected the median, but cold-starting 32 of them from the control loop still produced a **404 ms** heartbeat gap. Starting workers off-loop and admitting one launch at a time until it reported ready reduced the worst observed gap to **57 ms** (52 ms on repeat). All 32 then ran concurrently: this was launch admission, not a smaller workload. The design therefore requires **both** execution isolation and a launch budget. Do not set the production worker limit to 32 on this evidence.

Local Ubuntu 24.04 ARM64 container, Python 3.12.3, 2 CPUs, 2 GiB limit, no external network. Each of 32 contexts contains 600 user/tool-call/tool-result triples (~2.54 MB serialized, roughly 0.6M tokens; not tokenizer-measured). Each completes 80 mock requests, 2,560 total. A request deep-copies its graph, encodes its JSON, hashes the body and holds the graph over a simulated wait. A separate process sends a one-byte request on a local socket, waits for the controller's one-byte reply, then waits 10 ms; an internal 10 ms heartbeat records consecutive wake gaps **including** its nominal interval. Both run through cold startup and work completion. This measures an interactive control round trip, **not** a durable Stop receipt. Each isolated worker uses its own socket; model bodies never round-trip through the controller. The first two modes do not incur worker IPC.

| Execution | External control p99 / max (ms) | Worst heartbeat gap (ms) | Total wall time (s) | Controller peak RSS (MiB) |
|---|---:|---:|---:|---:|
| Work directly on event loop | 1,048 / 1,048 | 1,058 | 73.6 | 249 |
| Same interpreter, default thread executor | 337 / 582 | 595 | 66.7 | 282 |
| Exclusive processes, burst launch | 13 / 413 | 404 | 29.7 | 29 |
| Exclusive processes, paced off-loop launch | 14 / 19 | 57 | 28.1 | 29 |
| Same paced mode, fresh repeat | 12 / 18 | 52 | 28.3 | 29 |

All modes completed all requests with the same combined body digest. This checks the **synthetic** inputs, not the product prompt contract. The high-water mark for the *entire container* across the experiment was **763 MiB**, not the 29 MiB of the isolated controller. The prototype workers import only the standard library; do not multiply this RSS by a real Avibe worker count or use it to set a shipping memory budget. Separately, a worker stopped consuming its own output credit: its peer read the first byte and withheld further reads on a 4 MiB send. It was terminated after ten attempts of a healthy sibling; the sibling completed the remaining 70, exit 0, maximum gap between its completions 24.4 ms. This exercises independent streams and worker loss, **not** crash-safe persistence.

**Limits.** This is a sustained CPU stress comparison, not a simulation of 80 real upstream think times or growing history. Control probes are closed-loop (94 samples in the shared-loop run, >2,200 in each paced run); tail percentiles are descriptive, not matched-rate service SLOs. Both placement and launch concurrency change between the last two designs, so we cannot attribute the whole improvement to either in isolation. No provider SDK, real gateway, SQLite lock contention, OS-wide memory pressure, GUI delivery, Windows or packaged Mac startup was measured. Shared mode is an adverse architectural control, not a measurement of rc16. Before cutover, require a measured p99 and maximum for **durable** Send/Stop under responsive disk, delay-injected envelopes, slow subscribers and wedged workers. As provisional engineering gates on this fixture, aim for p99 control RTT <50 ms and no >200 ms control gap; measure queue wait and stopped acknowledgment separately, never claim this as a hardware-independent guarantee.

**Reproduce:** on an isolated, memory-limited Linux VM run `python3 proto.py MODE 32 80` for `shared`, `threaded`, `isolated`, `paced`, then repeat `paced`; run `python3 proto_fault.py` in the same directory. See `fixtures/interactive-control-isolation/` next to this document for stdlib-only scripts and the raw results. No prototype module is imported by Avibe. The next decision is whether to authorize slices 1–2 and a real worker-footprint pilot; implementation has not begun.
