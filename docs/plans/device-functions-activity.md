# Device functions and activity: backend contract for the Devices page

Status: proposed for rule review; no routes or migrations shipped by this document. Base: registry #4080 (`daeb126b3`); views compared at `c5e703e18` (#4084). Scope: instance-local routes/stores, no page wiring, native UI or control-plane changes.

| Actor / action | What would be lost or disclosed | Rule | Acceptance check |
|---|---|---|---|
| Remote person lists rows, reads status or changes a switch | Another person's device state | Use the registry's current binding, authenticated subject, live session and current role; recheck under the write lock. Members see only `mine`. Owners can inspect `others`, **not** change functions there. Unattributed rows are never theirs. Direct paired loopback has no signed subject; the registry's owner-at-login display grouping is not current ownership proof. Allow remote-device switches there only with independent current-owner proof; otherwise require a signed session. No mutation from setup LAN. | Two subjects in the same binding, same reported aliases/name; separate binding with same subject. Direct lookup, list, projected activity, cursor, and mutation must agree. Demoted Owner has no stale access. Owner can still use the distinct sign-out action. |
| Person switches notifications on own device | New delivery stops; sign-out and provider invalidation must not be undone | Off pauses only verified subscriptions for that logical device, and stays off across normal sync/rotation; on resumes only still-valid registrations paused by that switch. It cannot grant OS permission, recreate an endpoint, or revive a registration separately revoked/superseded. Return a typed reason if enrollment on-device is needed. Preserve disabled-but-resumable proven push-only row as an own visible target. | Disable A while B receives; refresh/rotate A while off; enable and list; invalidate or sign out A while off and check that on cannot restore the old subscription. Every enabled subscription remains reachable, including owner-only legacy buckets. |
| Person inspects or disconnects own Health; Owner inspects others | Kind/recency metadata; off destroys this pairing's synced days, sync metadata, credential usability and pending work | Only an independently proven link to the exact mobile device is eligible. The signed issuance of a one-time pairing code and its redemption can bind future pairs. Never infer from email, installation alias, name, newest mobile device, or OS. Expose only connected, consented kinds, latest successful sync; no enable route. Do not call the all-device revoke. | Two real mobile-store pairings and an outstanding pairing code: disconnect A, check B's days and code survive and A's credential and queued work no longer work. Canary values/errors never enter these routes/logs. A member cannot adopt the Owner's phone via self-report. |
| Person switches scheduling; Agent creates; phone claims/confirms | New proposals must not reach an off device; existing system items must survive | Default on for a capable device. Enforce at first delivery/claim under the transaction, scoped by authenticated device, **not** arbitrary payload device ID. Honor prior delivery for receipt/reconciliation and cancellation; do not remove native items. Creation today is untargeted: don't treat A's off switch as a global veto when B is eligible. Provide an actionable Agent-side status when delivery is blocked, not only an error to the polling phone. | A off, B on; no new lease/payload to A, B can claim. A's old confirmed alarm can still be canceled and its receipt reconciled. Repeated proposals with only A available yield a reason to stop and invite the person to enable the switch. No disclosure of someone else's device name. |
| Person reads Computer Use on the runtime host | Machine capability state | Host only; always read-only here. An unavailable/unverified controller must not be described as disabled or lacking permission. | Host is never mutable; other desktop/browser rows never inherit this state. Verify off, ready, missing permission, unavailable without exposing diagnostics. |
| Person signs out own device or Owner ends another person's access; self logout and bulk | Target session(s), independent Health pairing+data, push delivery and proposal access. Already-created native alarms remain | #4080 already tombstones SIDs, fences bulk enrollment and stops/reassigns Push transactionally. It does **not** revoke Health or fence schedule proposals. Tear down only proven resources for the last targeted logical device; preserve capabilities for a surviving session of the same device in single-SID logout or bulk. Prevent an issued-but-unredeemed pairing code or racing delivery from restoring access. Do not report deletion before targeted private-store cleanup succeeds; recovery must survive process death. | Individual, self and bulk, even with two SIDs on one phone; A removed while B stays; failure/restart between DB writes; pending pairing cannot complete after sign-out; old device cannot claim or upload. Fresh login doesn't resurrect old credentials. |
| Viewer reads sign-in/out and remote-access events | Membership history, who ended access | One new metadata-only event table. Log committed fresh sign-in once, never renewal/legacy enrollment; one sign-out per affected logical device with opaque subject-device and actor-device IDs. Record actual remote-access on/off transitions, not failed attempts, repeated start/stop, daemon restarts or tunnel outages. Host/CLI actor = `host` only when actually local. Binding-scoped owner sees instance transitions; member sees events on own devices. No cross-account actor details for members (redacted actor ref when necessary). | Idempotent retry, single/bulk/self, owner ending a member’s session, remote access restart without a state change. Stable device ID through registry promotion and after removal; no IP, UA, hostname, address or location payload. |
| Viewer reads Health access and schedule activity | Health values, private Session and alarm titles, raw receipts | Project directly from existing audit/operations, not a second event. Health read exposes only allowed metric kinds and range. Never persist a Session title in activity; only resolve at read time if permitted to read that Session. ## Proposed wire contract (not implemented)

* `GET /api/devices` keeps `{mine,others,unattributed,bulk_action}`. Preserve #4080's existing `capabilities.push_enabled`; add `functions: DeviceCapability[]` for the new container. Locale-neutral entries: `{kind:'notifications',on}`, `{kind:'health',on,data:HealthData[],syncedAt?:ISO8601}`, `{kind:'schedule',on}`, `{kind:'computerUse',on:boolean|null,fixed:true,status:'ready'|'needs_permission'|'off'|'unavailable'}`. `on` for computer use means verified opt-in, not necessarily readiness. Don't synthesize unsupported functions. Unproven Health association is not evidence that a phone has never synced.
* `PUT /api/devices/{id}/notifications`, `PUT /api/devices/{id}/schedule`: JSON `{on:boolean}`; return effective `function`. `GET /api/devices/{id}/health` returns only the Health entry; `POST /api/devices/{id}/health/revoke` returns the disconnected Health entry. No Health enable and no Computer Use write. Use existing CSRF and role policy; `404` for invisible/nonexistent target, `403` for a visible non-owned target, `409` when on-device enrollment/proof is needed. Typed errors only.
* `GET /api/devices/activity?limit=&cursor=&device_id=` and `GET /api/devices/{id}/health/reads?limit=&cursor=` return `{items,next_cursor}` with the same auth and order (suggest default 25, max 100). Each entry: `{id,at,device_id,kind,...}`; `at` UTC ISO, IDs opaque. `signedIn`; `signedOut` with nullable `actor_device_id`; `healthRead` with `data`, `from_day`, `to_day` and policy-dependent optional `task`; `alarmCreated`/`reminderCreated` with `confirmed` (no title or system identifier); `remoteAccessOn`/`remoteAccessOff` with actor device but no host address. No backfilled invented events.

## Decisions needed before implementation

1. Published #4080 aliases are **explicitly not ownership evidence**, and no shipping client on master calls `/api/devices/self`. Existing Health device records have private `id`, `installation_hash`, instance ID and **owner email**; preexisting `accesses` rows have **no mobile device ID, subject or binding**. True historical attribution and guaranteed targeted sign-out of existing pairs cannot both be delivered by a read-only projection. Propose recording scoped link at pairing issuance/redemption and `device_id` on future read audit writes, and a credential-backed authenticated attachment on-device for existing pairs. Unproven legacy history stays absent. Existing pairs cannot be claimed safely by approximate matches. Explicitly decide the upgrade/user path before claiming the destructive sign-out sentence universally. Targeted `MobileStore.revoke(device_id=…)` currently deletes *all* pending pairing codes; narrow only the targeted path and keep CLI-wide revoke intact. Private schema `user_version>1` currently fails on downgrade; design additive nullable columns with explicit upgrade/rollback tests.
2. Schedule `create_operation()` has no target, `claim_next()` binds the first eligible phone using its submitted installation ID; operation rows have no account/registry key. No source can definitively enumerate every future eligible phone. Propose capturing the verified registry identity at claim, retaining original record for projection, and reporting blocked-at-claim as evidence, not declaring every untargeted create failed. If immediate targeted Agent rejection is required, the Agent's operation contract must gain an optional explicit logical-device target; this is not just a page route.
3. #4084 uses a capability array, #4080 uses an existing object. The page adapter must map the additional `functions` field. `computerUse.on` alone cannot express missing permission vs unavailable; views also lack `remoteAccessOff`, `reminderCreated`, sign-out actor, exact Health range, and expect alarm labels/remote host strings. `healthConnected` and `directOn` are not requested backend events. Do not emit fabricated events, a location/host, synthetic labels or a fake boolean. Session title policy and missing/unavailable variants need agreement with the page lane.
4. Turning on notifications needs proof that an otherwise usable registration was paused by this switch; `enabled=0` alone also covers signed-out, replaced, manually unregistered and superseded registrations. No enable-by-flipping-all-disabled-rows. For server-side resumption distinguish switch pause from independent invalidation and keep proven paused rows addressable.
